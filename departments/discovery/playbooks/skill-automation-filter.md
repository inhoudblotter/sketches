# Skill: Automation Filter (Zero-Admin Assessment)

**Цель:** Принудительно задать вопрос «Нужен ли человек?» на этапе проектирования
домена — до того как разработка получает задание на функционал.

---

## 1. Иерархия замещения (Substitution Ladder)

Применяй в порядке приоритета: если верхний уровень применим — нижние не рассматриваются.

| Уровень | Тип | Когда применимо |
|---------|-----|-----------------|
| 1 | **Алгоритм / Правило** | Поведение полностью детерминировано: rate limit, авто-блокировка, авто-начисление |
| 2 | **AI-агент** | Решение требует суждения, но по обучаемым паттернам: L1 support, content moderation, fraud signal |
| 3 | **DAO-делегат** | Требуется доверие сообщества, не компании: curation, governance vote, appeals |
| 4 | **Workflow automation** | Человеко-управляемый, но без суждений: onboarding checklist, invoice generation |
| 5 | **FTE** | Только если уровни 1–4 неприменимы с явным `justification` |

---

## 2. Чек-лист режима `coverage.mode` отличного от `fte` (AI/DAO/Workflow/Algorithm)

Ставь автоматизированный режим (не `fte`), если ВСЕ четыре критерия выполнены:

- [ ] **Предсказуемость:** Входные данные структурированы, решение детерминировано или обучаемо.
- [ ] **Нет суждений о ценности:** Актор не принимает этических, эстетических или репутационных решений с непредсказуемыми последствиями.
- [ ] **Нет юридической ответственности:** Ошибка автоматизации не влечёт прямой правовой ответственности юрлица (не путать с риском — речь о персональной подписи под решением).
- [ ] **Нет эмоционального труда:** Взаимодействие с пользователем не требует эмпатии, деэскалации или ситуативного такта.

---

## 3. Чек-лист режима `coverage.mode: fte` (Человек обязателен)

Ставь `fte` если хотя бы один из критериев выполнен — и обязательно заполняй `justification`:

- **Юрисдикционная ответственность:** Решение требует подписи уполномоченного лица (compliance, KYC-верификация, юридические запросы).
- **Публичная репутация:** Ошибка автоматизации разрушает доверие сообщества или бренда необратимо (например: ложная блокировка публичной персоны).
- **Переговоры и партнёрства:** Взаимодействие требует отношений, контекста переговоров и дипломатии.
- **Кризисное управление:** Нестандартный сценарий с высокой ставкой, требующий человеческого суждения на месте.

---

## 4. Decision Tree для типовых ролей

```
L1 Support (FAQ / тикеты)
  → mode: ai_agent
  → by: AI chatbot (покрывает ~80% тикетов)
  → Остаток: escalation к L2/L3 FTE (уже не L1)

Content Moderation (правила платформы)
  → mode: ai_agent
  → by: AI-агент + DAO-апелляция
  → FTE только для appeals по флагам высокой срочности

Community Manager
  → mode: fte
  → justification: эмоциональный труд, репутация бренда, ситуативный такт
  → НО: автоматизируй рутину (кросс-постинг, digest, welcome msg) через workflow

Legal / Compliance Officer
  → mode: fte
  → justification: юрисдикционная ответственность, подпись под решением

DAO Curator (контент / реестр)
  → mode: dao_delegate
  → by: DAO delegate (community vote)
  → FTE не нужен; нужен протокол управления

Data Analyst (регулярные дашборды)
  → mode: workflow
  → by: workflow automation (scheduled reports)
  → FTE только для ad-hoc исследований (другая роль)
```

---

## 5. Правила заполнения `coverage`

```yaml
coverage:
  mode: 'ai_agent'
  by: 'AI chatbot'
  justification: >
    L1 support покрывается AI на ~80% по паттернам FAQ.
    Оставшиеся 20% эскалируются L2 — это уже другая роль.
```

```yaml
coverage:
  mode: 'fte'
  by: 'none'
  justification: >
    Compliance Officer подписывает KYC-решения юрлица.
    Юрисдикционная ответственность исключает автоматизацию
    по критерию «подпись уполномоченного лица».
```

---

## 6. Антипаттерны

- ❌ **`mode: fte` без `justification`** — запрещено. Каждый FTE требует обоснования.
- ❌ **`mode` отличный от `fte` для ролей с правовой ответственностью** — запрещено. Не путай «риск» и «юридическая подпись».
- ❌ **FTE как дефолт** — отсутствие анализа не равно необходимости FTE. Пройди чек-лист.
- ❌ **Смешивать уровни Substitution Ladder** — если применим уровень 1 (алгоритм), не назначай `mode: ai_agent`.
- ❌ **«Пока не автоматизировать»** — `mode` описывает архитектурную возможность, не MVP-приоритет. Если можно автоматизировать — ставь автоматизированный режим, даже если в MVP будет FTE на переходный период.
