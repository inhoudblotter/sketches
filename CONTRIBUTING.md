# CONTRIBUTING

MVP Develop Pipeline — это открытая система. Мы приветствуем всех, кто хочет улучшить агентов или добавить новые узлы в пайплайн. Ниже описаны базовые правила игры, чтобы мы могли работать в одном ритме.

## Установка окружения

Клонируйте репозиторий и изолируйте зависимости. Не устанавливайте пакеты глобально.

1. **Клон проекта**:

   ```bash
   git clone https://github.com/ВАШ_АККАУНТ/sketches.git
   cd sketches
   ```

2. **Изоляция (VENV)**:

   ```bash
   python -m venv venv
   source venv/bin/activate
   ```

3. **Установка зависимостей**:
   ```bash
   pip install -e .[dev]
   ```

*Примечание: Если вы создали нового агента или изменили `meta.yaml`, вам нужно пересобрать алиасы и обновить `pyproject.toml` командой:*
```bash
python3 scripts/build_system.py
```
*(Затем снова выполните `pip install -e .[dev]`, чтобы новые команды стали доступны в терминале).*

## Гигиена кода

Мы поддерживаем жесткие стандарты кода. Система не пропустит коммиты с синтаксическими ошибками или запутанной логикой. Перед пушем всегда проверяйте свой код локально:

- **Black** — строгий форматтер. Приводит весь код к единому стилю:
  ```bash
  black .
  ```
- **Ruff** — быстрый линтер. Ограничивает сложность кода и находит ошибки:
  ```bash
  ruff check .
  ```
  _(Можно использовать `--fix` для автоматического исправления простых ошибок)_
- **Mypy** — статический анализатор типов. Типы данных должны быть явными:
  ```bash
  mypy departments/
  ```
- **Pytest** — проверка тестами. Убедитесь, что ничего не сломалось:
  ```bash
  pytest
  ```

## Правила коммитов (Conventional Commits)

Мы используем стандарт **Conventional Commits** для формирования понятной истории проекта. Сообщения коммитов должны иметь следующую структуру:
`<тип>(<контекст>): <описание>`

Основные типы:

- `feat`: добавление нового функционала или агента.
- `fix`: исправление бага.
- `docs`: изменения только в документации.
- `refactor`: рефакторинг кода без изменения логики работы.
- `test`: добавление или исправление тестов.
- `chore`: обновление зависимостей, настройка CI/CD и прочие технические задачи.

## Внедрение изменений (Pull Request)

1. Создайте новую ветку от `main` (например, `feature/new-agent` или `bugfix/parser`).
2. Сделайте четкий и понятный коммит.
3. Отправьте ветку в свой форк.
4. Откройте **Pull Request**.

Сразу после создания PR автоматика (GitHub Actions) прогонит ваш код через проверки Black, Ruff, Mypy и Pytest. Если скрипты найдут ошибку, исправьте код локально и сделайте новый коммит в ту же ветку. Мы принимаем PR только с полностью пройденными проверками.

Если вы планируете серьезные изменения в архитектуре, создайте **Issue** для предварительного обсуждения.
